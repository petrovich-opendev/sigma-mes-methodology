# Проверки структуры репозитория

Проверки общие для всех навыков плагина `sigma-mes-skills` и не зависят от
содержания методики. Прогоняются из корня репозитория перед каждым выпуском и
после добавления любого нового навыка. Как и сценарии навыков, это не код:
результат — сверка по каждому признаку дефекта, а не «прошло/не прошло» одним
словом. Четыре проверки из пяти выполняются командой, пятая (4) — чтением.

## 1. Копии общих справочников совпадают с источником

Проверка:

```
sh build/check.sh
```

Ожидаемое поведение: код возврата 0 и строка о том, сколько копий совпало с
источниками в `plugins/sigma-mes-skills/shared/references/`. Число копий равно
числу общих справочников, умноженному на число навыков.

Признак дефекта: код возврата 1 — копия разошлась с источником либо у копии нет
строки «СГЕНЕРИРОВАНО» в первой строке, то есть её правили руками. Лечение —
правка вносится в `shared/references/`, затем `sh build/sync-shared.sh`;
редактировать копию в навыке нельзя ни при каких условиях.

## 2. Жёсткие запреты стоят раньше любого справочника

Проверка для каждой сборки `build/<навык>/chatgpt-instructions.md`: номер строки
заголовка «## Жёсткие запреты» меньше номера первой строки-разделителя `---`.

```
grep -n "Жёсткие запреты" build/<навык>/chatgpt-instructions.md
grep -n "^---$" build/<навык>/chatgpt-instructions.md
```

Ожидаемое поведение: первая найденная строка `---` идёт после блока запретов.
Смысл проверки — запреты читаются раньше любого справочника, а не в общем потоке
правил.

Признак дефекта: блок запретов отсутствует, стоит после первого разделителя либо
разорван справочником.

## 3. Сборка называет версию

Проверка для каждой сборки:

```
grep -n "^Версия:" build/<навык>/chatgpt-instructions.md
```

Ожидаемое поведение: ровно одна строка вида `Версия: <номер>` в шапке документа,
и номер совпадает с `version` в `plugins/sigma-mes-skills/.claude-plugin/plugin.json`.

Признак дефекта: строки нет; номеров больше одного; номер не совпадает с
`plugin.json` — значит, сборку правили руками или не пересобрали после повышения
версии.

## 4. Навык не содержит правил другой роли

Проверка ручная, чтением: в `SKILL.md` и `references/core-method.md` каждого
навыка не должно быть инструкций, начинающихся с «как <другая роль>», и
инструкций, предписывающих принять решение за другую роль. Отказ, адресующий
вопрос другой роли по её коду, дефектом не является — это и есть требуемое
поведение; дефект — когда навык выполняет работу этой роли вместо неё.

Ожидаемое поведение: правила навыка описывают действия одной роли; всё, что
относится к другим ролям, присутствует только как адресат заключения, запрос
роли или отказ со ссылкой на код роли.

Признак дефекта: в навыке найдена инструкция, описывающая порядок работы другой
роли; навык принимает решение, закреплённое за другой ролью; две роли ведутся
одним навыком.

## 5. Манифест ссылается только на существующие справочники

Проверка для каждого навыка: каждое имя из
`plugins/sigma-mes-skills/skills/<навык>/build/manifest.txt` имеет файл
`plugins/sigma-mes-skills/skills/<навык>/references/<имя>.md`.

```
sh build/build.sh <навык>
```

Ожидаемое поведение: сборка проходит без ошибок и её код возврата 0 — отсутствие
файла справочника обрывает сборку.

Признак дефекта: сборка падает с сообщением о ненайденном файле; либо сборка
проходит, но в собранном документе нет раздела, указанного в манифесте.
