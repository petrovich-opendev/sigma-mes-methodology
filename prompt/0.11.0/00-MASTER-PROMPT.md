# Главный промпт: сгенерировать sigma-mes-skills 0.11.0 для ChatGPT и Codex

## Кто ты и что делаешь

Ты — исполнитель в репозитории плагина `sigma-mes-methodology`. Твоя задача — создать плагин `sigma-mes-skills` версии 0.11.0 в переносимом формате Agent Plugins для ChatGPT (режимы Codex и Work) и Codex. Плагин содержит четыре навыка:
- владелец продукта;
- функциональный архитектор;
- технический архитектор;
- гейты.

Всё содержание плагина берётся из этого пакета. Пакет лежит в `prompt/0.11.0/`.

## Главные правила исполнения

1. **Не додумывай.** Если в пакете нет ответа:
   - запиши вопрос в `plugins/sigma-mes-skills/OPEN-QUESTIONS.md` с номером Q-101 и далее;
   - этот элемент не реализуй;
   - продолжай остальную работу.
2. **Решения D-01…D-19** из `01-DECISIONS.md` обязательны. Не меняй их и не предлагай альтернатив.
3. **Нормативные тексты** — роли, правила, гейты, термины, коды — бери только из `context/constitution-v0.9.extract.yaml` и `context/acceptance-regulation-v0.1.extract.yaml`. Не пересказывай полномочия ролей: вставляй дословно, где это указано в спецификации.
4. **Не изменяй и не удаляй** файлы прежнего плагина версии 0.10.0 для Claude Code.
5. **Не записывай** в репозиторий токены, пароли, адреса серверов, которых нет в пакете. Заполнители вида `<...>` оставляй как есть.
6. **Язык** всех текстов для пользователя — русский.
7. **Проверки.** После каждого шага выполни его проверку. Если она не проходит, исправь и повтори. Переходи к следующему шагу только после успешной проверки.
8. **Если каталог уже есть.** Если `plugins/sigma-mes-skills/` или `plugin-src/shared/` уже существуют до начала работы, остановись и сообщи. Ничего не перезаписывай.

## Входы

Прочитай все файлы пакета в порядке из `README.md`. До окончания чтения ничего не создавай.

## Шаги

### Шаг 1. Инвентаризация

**Действие.** Составь список файлов пакета и проверь, что все файлы из `README.md` на месте. Выполни:

```
git status
git rev-parse HEAD
```

Запомни исходный коммит для проверки S-12.

**Проверка.** Все файлы пакета существуют. Каталогов `plugins/sigma-mes-skills/` и `plugin-src/shared/` нет. Если файл `.agents/plugins/marketplace.json` уже есть, не перезаписывай его, а на шаге 5 добавь в него одну запись по D-02; это единственный отслеживаемый git файл, который разрешено изменить.

### Шаг 2. Каркас

**Действие.** Создай дерево каталогов из `spec/plugin-layout.md`, раздел «Дерево». Файлов пока не заполняй, кроме пустых каталогов.

**Проверка.** Все каталоги из дерева существуют. Лишних каталогов нет.

### Шаг 3. Общие справочники в `plugin-src/shared/`

**Действие.**
1. `session-protocol.md` — побайтная копия `spec/session-protocol.md`.
2. `constitution.extract.yaml` — побайтная копия `context/constitution-v0.9.extract.yaml`.
3. `acceptance-regulation.extract.yaml` — побайтная копия `context/acceptance-regulation-v0.1.extract.yaml`.
4. `config-template.yaml` — побайтная копия `spec/config-template.yaml`.
5. `codes.yaml` — по разделу «codes.yaml» в `spec/plugin-layout.md`. Раздел `allowed_codes` — дословно из `checks/normative-checks.yaml`.
6. `deprecated.yaml` — все записи `roles` и `terms` со `status: deprecated` из извлечения Конституции, с полями `id`, `name`, `replacement`, `reason` (если есть).
7. `artifact-schemas/<тип>.schema.json` — для каждого типа из `spec/artifacts.yaml`, раздел `types`. Правила преобразования:
   - общие поля `common.frontmatter` входят в каждую схему;
   - `required: true` → в `required`;
   - `enum` → `enum`;
   - `enum_text` → `enum` из русских строк;
   - `const` → `const`;
   - `min_items` → `minItems`;
   - `ref_pattern` → `pattern`;
   - `type: list of string` → массив строк;
   - `type: list` с `item` → массив объектов;
   - условные правила из `validation` и `common.validation`, которые выражаются в JSON Schema, — через `if`/`then`;
   - остальные правила из `validation` реализуй в `check_normative.py` (шаг 7) и перечисли в `description` схемы.
8. `templates/<тип>.md` — YAML-шапка со всеми полями схемы (пустые значения, `ai_assistance.plugin_version: 0.11.0`, `approval.recorded: false`) и заголовки разделов тела из `body_sections` плюс `common.body_sections_always`, без дублей, в указанном порядке.

**Проверка.**
- `cmp` для копий 1–4.
- Все JSON-файлы валидны: `python3 -m json.tool`.
- Число схем и шаблонов равно числу типов.

### Шаг 4. Навыки

**Действие.** Для каждой спецификации `spec/skill-*.md` создай `plugins/sigma-mes-skills/skills/<имя>/SKILL.md`:
1. Шапка — дословно из раздела «Шапка SKILL.md» спецификации.
2. Разделы — в порядке «Разделы SKILL.md» спецификации.
3. В разделе «Протокол сеанса» напиши:
   - обязательство выполнить `references/session-protocol.md` (шаги S1–S6, правила R1–R10);
   - краткий перечень шагов S1–S6 одной строкой каждый;
   - формат ответа, начиная со строки `Активная роль:`.
4. «Полномочия роли» — дословная вставка полей `responsibility` и `authority` роли из извлечения Конституции.
5. Для `sigma-gates` разделы «Общее правило гейта» и «Гейты» — дословно из извлечения.
6. Режимы — все, что есть в спецификации, с тем же кодом и названием в заголовке (`### PO-1. Описание продукта` и так далее). Поля «Вход», «Шаги», «Выход», «Основания», «Запрещено» — по спецификации, без сокращения смысла. Можно дополнять только ссылками на `references/`: шаблоны, схемы, извлечения.
7. В каждом навыке явно упомяни RULE-AI-001 (ИИ не принимает решений) и RULE-AI-002 (только действующие редакции) в разделе «Протокол сеанса».
8. Таблицы в SKILL.md не используй.

**Проверка.**
- Проверки S-03, S-04, S-05 из `checks/structural-checks.md`.
- Раздел `required_in_every_skill` из `checks/normative-checks.yaml`.

### Шаг 5. Манифест, маркетплейс, документы плагина

**Действие.**

2. `.agents/plugins/marketplace.json` — дословно из `spec/plugin-layout.md`.
3. `INSTALL.md` — по разделу «INSTALL.md» в `spec/plugin-layout.md`, шесть разделов в указанном порядке.
4. `README.md` плагина:

   - четыре навыка и их режимы (коды и названия);
   - основание — Конституция 0.9 (черновик) и Регламент 0.1 (черновик);

   - переход на формат Agent Plugins для ChatGPT и Codex;
   - роли по Конституции 0.9;

   - версия 0.10.0 не изменялась.
6. `OPEN-QUESTIONS.md` — копия `OPEN-QUESTIONS.md` пакета; в конец — твои вопросы Q-101 и далее, если появились.

**Проверка.** S-01, S-02, S-10, S-11.

### Шаг 6. Синхронизация справочников

**Действие.** Создай `build/codex/sync-shared.sh`:
1. Удаляет `skills/*/references/`.
2. Копирует `plugin-src/shared/` целиком в `skills/<навык>/references/` каждого из четырёх навыков.

Скрипт идемпотентен. Запусти его.

Скопируй `prompt/0.11.0/tools/extract_constitution.py` в `build/codex/extract_constitution.py` без изменений.

**Проверка.** S-06.

### Шаг 7. Проверки

**Действие.** Создай:
- `build/codex/checks/check_structure.py` — все проверки S-01…S-12 из `checks/structural-checks.md`;
- `build/codex/checks/check_normative.py` — все разделы `checks/normative-checks.yaml`:
  - `id_checks` — каждый найденный идентификатор есть в извлечениях;
  - `deprecated`;
  - `required_in_every_skill`;
  - `forbidden_in_skills`;
  - `decision_integrity` — на примерах из `fixtures/`;
  - `fa_technical_markers` — только предупреждение;
- `build/codex/checks/fixtures/` — по одному корректному примеру каждого типа артефакта и три некорректных:
  - `gate-decision` с GO при `go_excluded = true`;
  - `deployment-architecture` без `rollback`;
  - `term-proposal` с полем статуса.

  Некорректные примеры должны отвергаться проверками;
- `build/codex/checks/run-all.sh` — запускает `sync-shared.sh`, затем обе проверки. Код возврата 0 только при отсутствии `FAIL`.

Для PyYAML и jsonschema используй `python3 -m pip install --user`, если их нет. Других зависимостей не добавляй.

**Проверка.** `bash build/codex/checks/run-all.sh` завершается с кодом 0. Проверка fixtures пройдена, если каждый корректный пример принят, а каждый из трёх некорректных отвергнут с понятной причиной.

### Шаг 8. Самопроверка по сценариям

**Действие.** Пройди `checks/scenario-tests.md` мысленно по тексту SKILL.md. Если положения нет, дополни SKILL.md в рамках спецификации. Если спецификация этого не покрывает, запиши вопрос Q-101 и далее.

**Проверка.** У каждого из 17 сценариев есть ссылка на положение.
