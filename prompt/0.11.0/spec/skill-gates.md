# Спецификация навыка sigma-gates

## Шапка SKILL.md (дословно)

```yaml
---
name: sigma-gates
description: Правила гейтов Конституции разработки СИГМА.MES+ (GATE-01–GATE-06). Использовать, чтобы подготовить пакет гейта с проверкой обязательных заключений, доказательств, прослеживаемости и расхождений статусов, подготовить форму заключения роли, у которой нет своего навыка, или записать решение ответственной роли GO, REWORK, STOP (для GATE-05 также RETIRE) со слов человека.
---
```

## Разделы SKILL.md (в этом порядке)

1. Назначение.
2. Протокол сеанса — `references/session-protocol.md`, шаги S1–S6, правила R1–R10. На шаге S2 допустима «Другая роль» с указанием кода: она готовит материалы, а запись решения (режим G-3) доступна только ответственной роли гейта по разделу 3.2.
3. Общее правило гейта — дословно раздел 3.1 из `constitution.extract.yaml`.
4. Гейты — для каждого GATE-01–GATE-06 дословно:
   - цель;
   - состояние результата;
   - ответственная роль;
   - обязательные заключения (`stages_gates` из `constitution.extract.yaml`).
5. Режимы.
6. Перед выдачей.

## Режимы

### G-1. Пакет гейта

**Вход.**
- Код гейта.
- Оцениваемый результат: область, редакции материалов, коммит или тег.
- Материалы, указанные пользователем.

**Шаги.**
1. Найди в `stages_gates` запись гейта: ответственную роль и обязательные заключения.
2. Для каждого обязательного заключения:
   - найди файл `role-conclusion` этой роли в `paths.gates`;
   - отметь `present: true/false`;
   - укажи путь.
3. Перечисли доказательства со ссылками: результаты проверки, записи функциональной приёмки, ADR. Отметь, что достаточность доказательств определяет ROLE-VERIFICATION-OWNER (полномочия роли, TERM-EVIDENCE).
4. **Прослеживаемость (раздел 3.1).** Для каждого изменения в результате проверь цепочку: задача → требование → проектные материалы → реализация → результаты проверки. Разрыв цепочки — блокирующий пункт.
5. **Расхождение статусов (раздел 3.1).** Если сведения ведутся в нескольких системах, перечисли расхождения статусов. Неустранённое расхождение — блокирующий пункт.
6. **Для GATE-03 и GATE-04.** Перечисли исходы функциональной приёмки. Блокирующий пункт:
   - функциональность без приёмки;
   - исход RETURNED;
   - исход REJECTED_ARCHITECTURALLY.

   Исход ACCEPTED_WITH_REMARKS решению GO не препятствует.
7. **Блокирующие пункты:**
   - отсутствие обязательного заключения;
   - отсутствие доказательства;
   - неустранённое противоречие;
   - расхождение статусов;
   - пункты шага 6.

   Поле `go_excluded` = true, если есть хотя бы один блокирующий пункт.
8. Добавь в пакет напоминание дословно из раздела 3.1: совещание, наличие документа, успешная автоматическая проверка, результат ИИ или отдельный статус в информационной системе сами по себе не означают прохождение гейта.

**Выход.** Артефакт `gate-package` в `paths.gates/<GATE>/<идентификатор результата>/`.

**Основания.** Разделы 3.1 и 3.2, RULE-ACCEPTANCE-006.

**Запрещено.** Рекомендовать решение GO, REWORK или STOP. Пакет содержит факты и блокирующие пункты, а не решение.

### G-2. Форма заключения роли без собственного навыка

**Применение.** Роли:
- ROLE-PROJECT-MANAGER;
- ROLE-VERIFICATION-OWNER;
- ROLE-SERVICE-OWNER;
- ROLE-SECURITY-OWNER;
- ROLE-INDEPENDENT-REVIEWER.

**Шаги.**
1. Подготовь форму `role-conclusion`:
   - гейт;
   - роль;
   - перечень вопросов, которые роль должна рассмотреть по своей ответственности и полномочиям (дословно из `roles` в `constitution.extract.yaml`);
   - поля для замечаний со ссылками на положения.
2. Содержание заключения не заполняй за роль.
3. Для ROLE-INDEPENDENT-REVIEWER итог — только PASS, REWORK или STOP-RECOMMENDED; он не подменяет ответственную роль гейта.
4. Для остальных ролей итог — текстом, без кода: Конституция кода для него не задаёт (D-10).

**Выход.** Артефакт `role-conclusion` с пустыми полями содержания.

**Основания.** Раздел 3.2, полномочия ролей в разделе 4.2.

### G-3. Запись решения по гейту

**Вход.** Пакет гейта (`gate-package`) и явная реплика человека в ответственной роли этого гейта в текущем сеансе.

**Шаги.**
1. Проверь, что человек действует в ответственной роли этого гейта (шаг S2 и раздел 3.2). Если роль другая, решение не записывай и назови ответственную роль.
2. Проверь код решения:
   - GO, REWORK или STOP;
   - RETIRE — только для GATE-05.
3. Если решение GO, а в пакете `go_excluded` = true:
   - решение не записывай;
   - перечисли блокирующие пункты;
   - процитируй положение раздела 3.1, которое исключает GO.

   Предложи REWORK или устранение пунктов. Решение остаётся за человеком.
4. Запиши:
   - решение;
   - дословную цитату реплики;
   - роль;
   - дату;
   - ссылку на пакет.

   Решение хранится отдельно от заключений ролей.

**Выход.** Артефакт `gate-decision`.

**Основания.** Раздел 3.1, TERM-GATE, RULE-AI-001.

**Запрещено.** Записывать решение без реплики человека и выводить решение из заключений.

## Перед выдачей

1. Каждое обязательное заключение из раздела 3.2 отражено в пакете как присутствующее или отсутствующее.
2. `go_excluded` вычислен по правилам шага G-1.7.
3. Решение записано только цитатой и только ответственной ролью.
4. Коды — только из `allowed_codes`.
5. Раздел «Передать» артефакта заполнен: вопросы, не относящиеся к гейту, с ролью-получателем, либо «—».
