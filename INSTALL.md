# Установка и работа

Плагин один: `sigma-mes-skills` версии 0.11.3 для ChatGPT для десктопа (установка в режимах
Codex или Work; навыки работают и в обычном режиме чата, и в проекте чата) и Codex CLI.
Расширение Codex для IDE плагины не поддерживает. Подробная установка — в
`plugins/sigma-mes-skills/INSTALL.md`; здесь общий порядок и то, что относится к самому
репозиторию.

## Коротко

1. Подключить маркетплейс:

   ```
   codex plugin marketplace add petrovich-opendev/sigma-mes-methodology
   ```

   и установить `sigma-mes-skills` из Plugins Directory (ChatGPT для десктопа, после
   перезапуска) или через `/plugins` в Codex CLI — подробно в
   `plugins/sigma-mes-skills/INSTALL.md`, разделы 2 и 3. Кто ставил 0.11.0, обновляется
   командой `codex plugin marketplace upgrade sigma-mes`.
2. Открыть новый чат и вызвать любой навык (`@` в ChatGPT, `$` или `/skills` в Codex CLI):
   он покажет список ролей и попросит выбрать.
3. Работать. Прикладывайте свои материалы — описание сервиса, заметки, прежние артефакты:
   навык берёт из них ответы.

Больше ничего не нужно. Плагин самодостаточен: Конституция разработки 0.9 и Регламент
функциональной приёмки 0.1 встроены в него дословно.

## Что можно подключить дополнительно

Ни одно из этого не нужно для начала работы — только расширяет возможности:

- **Реестр терминов** как MCP-сервер `sigma_terms` в `~/.codex/config.toml`. Без него навык
  сверяет термины с приложением A встроенной Конституции. Токен хранится только в
  переменной окружения; записывать его в файлы репозитория запрещено.
- **`sigma-mes.config.yaml`** в корне рабочего репозитория документации — шаблон лежит в
  `plugin-src/shared/config-template.yaml`. С ним навык сохраняет артефакты по путям и сверяет
  встроенную Конституцию с опубликованной. Незаполненные пути навык пропускает.
- **Опубликованные условия применения ИИ** (RULE-AI-001) — путь в `sigma-mes.config.yaml`.
  С ними навык их соблюдает; без них работает и отмечает в каждом артефакте, что он
  подготовлен без утверждённых условий.

## Работа с самим репозиторием

Общие справочники ведутся в `plugin-src/shared/`. После правки — разложить копии по навыкам:

```
sh build/codex/sync-shared.sh
```

Перед коммитом — приёмка:

```
sh build/codex/checks/run-all.sh
```

Нужен git-клон, а не распакованный архив: проверка размещения файлов берёт перечень
файлов из git.

Зависимости: `python3`, `PyYAML`, `jsonschema`. Установка:

```
python3 -m pip install --user PyYAML jsonschema
```

В системах с PEP 668 (externally managed environment) добавьте `--break-system-packages`.

## Обновление версий Конституции и Регламента

Плагин собран для Конституции 0.9 и Регламента приёмки 0.1: значения записаны в
`plugin-src/shared/codes.yaml`, блок `built_for`. Пока плагин не обновлён, основание для
ролей, правил и гейтов — встроенные тексты этих редакций, даже если в рабочем репозитории
опубликована другая; значения терминов — из реестра, если он подключён.

Если в рабочем репозитории задана опубликованная Конституция другой версии, навык одной
строкой предупредит о расхождении и продолжит работу по встроенной редакции, отметив
расхождение в артефакте. Работа не останавливается.

Новая редакция приходит в плагин новым пакетом промпта — так же, как редакция 0.9 пришла
пакетом `prompt/0.11.0/`. Проверка S-08 сверяет встроенные извлечения побайтно с
извлечениями пакета и ищет в `built_for` версии 0.9 и 0.1, поэтому одно лишь новое
извлечение и правка `built_for` дадут FAIL. Порядок:

1. Новый пакет кладётся в `prompt/<версия>/`; каталог `prompt/0.11.0/` не правится.
2. Документ .docx переводится в Markdown (например, `pandoc -t gfm`), извлечения снимаются
   `build/codex/extract_constitution.py` в `plugin-src/shared/` и сверяются с пакетом.
3. Правится `built_for` в `plugin-src/shared/codes.yaml`. Версия плагина поднимается
   одинаково в `plugins/sigma-mes-skills/plugin.json`, `built_for.plugin_version`, схемах
   (`plugin-src/shared/artifact-schemas/`, проверка S-01), шаблонах
   (`plugin-src/shared/templates/`) и примерах (`build/codex/checks/fixtures/`, проверка S-09).
   Правятся тексты, где редакции названы явно: протокол сеанса, SKILL.md, `plugin.json`
   (`longDescription`), README, INSTALL. Затем `sh build/codex/sync-shared.sh`.
4. На новый пакет переводятся константа `PROMPT` в `build/codex/checks/check_structure.py`
   (её читают S-03, S-08, S-09) и `SPEC` в `build/codex/checks/check_normative.py`; в S-08
   правятся имена файлов извлечений и ожидаемые версии, а если версия плагина уходит с
   линии 0.11.x — и регулярное выражение в S-01. Прогоняется приёмка.
