# Установка и работа

Плагин один: `sigma-mes-skills` версии 0.11.0 для ChatGPT (режимы Codex и Work) и Codex
(CLI, IDE). Подробная установка — в `plugins/sigma-mes-skills/INSTALL.md`; здесь общий порядок
и то, что относится к репозиторию.

## Коротко

1. Установить плагин по `plugins/sigma-mes-skills/INSTALL.md`.
2. Скопировать `plugin-src/shared/config-template.yaml` в корень **рабочего** репозитория
   документации как `sigma-mes.config.yaml` и заполнить все заполнители `<...>`.
3. Убедиться, что опубликованы условия применения ИИ: без них работа по проекту не
   разрешена (RULE-AI-001).
4. Запустить любой навык: он выполнит шаги S1–S6 протокола сеанса и попросит выбрать роль.

## Что нужно на рабочем месте

- Персональный ПК и VPN до защищённого сегмента: опубликованные материалы и реестр терминов
  доступны только оттуда.
- ChatGPT для десктопа (Codex или Work) либо Codex CLI или IDE. Обычный режим чата не
  подходит: он работает из облака и файлов рабочего репозитория не видит. Навык это
  обнаруживает на шаге S1 и нормативных материалов не создаёт.

## Реестр терминов

Реестр подключается пользователем в `~/.codex/config.toml` как MCP-сервер `sigma_terms`.
Токен хранится только в переменной окружения; записывать его в файлы репозитория запрещено.
В плагин сервер не встраивается: средство ведения реестра определяет
ROLE-DOCUMENTATION-OWNER, доступ средств ИИ разрешает ROLE-AI-USE-CASE-OWNER (RULE-TERM-003).

Если сервер недоступен, навык продолжает работу, но помечает каждое употребление критичного
термина результатом `TERM_NOT_DEFINED`, и решения, зависящие от такого термина, не готовит
как окончательные (RULE-TERM-001).

## Работа с самим репозиторием

Общие справочники ведутся в `plugin-src/shared/`. После правки — разложить копии по навыкам:

```
sh build/codex/sync-shared.sh
```

Перед коммитом — приёмка:

```
sh build/codex/checks/run-all.sh
```

Нужен полный клон: проверка размещения файлов и сверка с историей работают по git. В
поверхностном клоне (`--depth 1`) проверки честно сообщат, что неприменимы.

Зависимости: `python3`, `PyYAML`, `jsonschema`. Установка:

```
python3 -m pip install --user PyYAML jsonschema
```

В системах с PEP 668 (externally managed environment) добавьте `--break-system-packages`.

## Обновление версий Конституции и Регламента

Плагин собран для Конституции 0.9 и Регламента приёмки 0.1: значения записаны в
`plugin-src/shared/codes.yaml`, блок `built_for`. На шаге S4 навык сверяет версию из паспорта
опубликованной Конституции с этим значением и при расхождении нормативных материалов не
создаёт (раздел 5.4).

Поэтому при выходе новой редакции Конституции или Регламента плагин обновляется: заново
снимается извлечение (`build/codex/extract_constitution.py`), правится `built_for`, и
прогоняется приёмка. До обновления плагин честно отказывается работать по проекту — это
предусмотренное поведение, а не сбой.
