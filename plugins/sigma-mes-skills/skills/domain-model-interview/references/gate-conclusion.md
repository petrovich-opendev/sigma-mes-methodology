# Формат заключения роли к гейту

Справочник фиксирует форму заключения, которое роль даёт к гейту: человеческую проекцию, машинную проекцию и правила их соответствия. Формат общий для всех ролей и всех гейтов; что именно роль проверяет, прежде чем дать заключение, формат не задаёт — чек-лист роли живёт в навыке этой роли.

## Чем заключение является и чем не является

Заключение — вход для решения ответственной роли гейта, а не само решение. Роль, дающая заключение, отвечает на вопрос своей дисциплины: что в предъявленном материале она считает достаточным, чего недостаёт и что из недостающего препятствует переходу на следующий этап. Решение по гейту — GO, REWORK, STOP — принимает ответственная роль этого гейта, опираясь на все обязательные заключения и на доказательства (см. `roles-gates.md`, разделы «Решения гейта» и «Правило гейта»).

Отсюда прямое следствие: **заключение не содержит и не может содержать метку GO, REWORK или STOP**. Ни в одном поле, ни в тексте замечания, ни в вердикте. Роль, дающая заключение, не голосует за решение и не рекомендует его — она сообщает состояние предмета в своей зоне ответственности. Формат записи решения — в `gate-decision.md`.

По `RULE-AI-001` навык материал к заключению готовит, но заключения не даёт: проект заключения становится заключением **только после явной реплики носителя роли в форме «даю заключение»**. Реплики «согласен», «всё верно», «ок», «отправляй» заключением не являются: навык называет требуемую форму и ждёт её. До этого `document_status` — «проект заключения», и ни один файл не называется заключением.

Правило то же, что у решения по гейту в `gate-decision.md`, и по той же причине: подпись роли под документом — действие человека, и вывести её из согласия в разговоре нельзя.

## Вердикт

Вердикт принимает ровно три значения:

| Значение | Когда |
|---|---|
| замечаний нет | Массив `findings` пуст. |
| замечания не блокируют | Замечания есть, и у всех `blocking: false`. |
| есть блокирующие замечания | Хотя бы у одного замечания `blocking: true`. |

Вердикт — не суждение навыка и не отдельное решение роли: он механически выводится из признака `blocking` у замечаний. Изменить вердикт, не меняя состава замечаний, нельзя; изменить его «потому что по существу не страшно» — тоже: если замечание не блокирует, это записывается в самом замечании признаком `blocking: false`, а не правкой вердикта.

## Машинная проекция (gate-conclusion.yaml)

### Верхнеуровневые поля

| Поле | Назначение |
|---|---|
| `product_id` | Идентификатор продукта — тот же, что в `description.yaml`. |
| `version` | Номер редакции самого заключения, начиная с 1. Растёт при каждом повторном заключении той же роли к тому же гейту: после доработки по REWORK роль даёт заключение заново, и по номеру видно, какое из них последнее. Не путать с `based_on` — это версии входа, а не самого документа. |
| `gate` | Код гейта (`GATE-01` … `GATE-06`). |
| `role` | Код роли, дающей заключение. |
| `holder` | Носитель роли — берётся из `roles_declared` приложенного описания; если роль в `roles_declared` не названа, записывается «не назван», если названа как незанятая — «не назначена». Носитель не выводится из контекста разговора. |
| `based_on` | Объект: `description_version` — версия описания, по которому дано заключение; `domain_version` — присутствует только при наличии предметной модели. Заключение всегда относится к конкретным версиям входа, а не к продукту вообще. |
| `date` | Дата заключения. |
| `document_status` | «проект заключения» либо «заключение дано». |
| `verdict` | Одно из трёх значений выше. |
| `role_combination_note` | Строка о совмещении ролей; поле отсутствует, если совмещения нет. |
| `process_references` | Ссылки на процессную опору — те же поля, что в `description-schema.md`. |

### Массив `findings`

Каждый элемент — одно замечание.

| Поле | Назначение |
|---|---|
| `id` | Идентификатор замечания (`F-001`). Устойчив в пределах документа; при изменении текста замечания не меняется. |
| `text` | Текст замечания на русском языке: что именно недостаёт или вызывает возражение. |
| `refers_to` | Список идентификаторов, к которым замечание относится: `ST-…` (положения описания), `OQ-…` (открытые вопросы), `RR-…` (запросы ролям). Пустым не бывает: замечание без адреса в предъявленном материале не формулируется — оно не проверяемо. |
| `blocking` | `true` либо `false`. Признак того, препятствует ли замечание переходу на следующий этап. Заполняется по правилу чек-листа роли, а не по впечатлению. |
| `addressed_to` | Код роли, которой адресовано замечание, — кто может его снять. |
| `formulated_by` | Автор формулировки: пользователь или ИИ. Те же значения, что в `statuses.md`. |

Порядок элементов значения не имеет: в человеческой проекции блокирующие замечания выводятся первыми независимо от порядка в массиве.

## Человеческая проекция (gate-conclusion.md)

Документ открывается шапкой: продукт, гейт, роль и её носитель, на какие версии опирается заключение (описание, при наличии — предметная модель), дата, статус документа. Если совмещение ролей есть — строка о совмещении идёт в шапке, без оценки: оценивает его ответственная роль на гейте.

Дальше — вердикт одной строкой, теми же словами, что в машинной проекции.

Дальше — замечания списком, блокирующие первыми; в каждом: идентификатор, текст, к чему относится, кому адресовано, блокирует или нет. Если замечаний нет, так и пишется одной строкой — пустой раздел не выводится.

Документ заканчивается фразой о том, чем заключение не является: это не решение по гейту, не утверждение требований, не подтверждение достаточности доказательств за пределами зоны роли и не разрешение перехода на следующий этап.

## Файлы и хранение

Шаблон заключения — `shared/templates/gate-conclusion-template.md` и `.yaml`. Он общий: заключение к гейту даёт любая роль, а не только та, у которой есть навык.

Имена постоянные: `docs/product/<product-id>/gates/<GATE-NN>/<ROLE-CODE>.md` и `.yaml`. Сохранение файлов выполняет носитель роли сам; навык называет путь и выдаёт содержимое, но не утверждает, что файл сохранён.
