# Формат записи решения по гейту

Справочник фиксирует форму, в которой записывается решение ответственной роли по гейту: человеческую проекцию, машинную проекцию и правила допустимости. Формат общий для всех гейтов.

## Чем решение является и чем не является

Решение по гейту — человеческий акт ответственной роли этого этапа, принятый на основании обязательных заключений ролей и доказательств, которые должны быть достаточными, актуальными и относимыми к предмету решения (см. `roles-gates.md`, разделы «Решения гейта» и «Правило гейта»).

Решением не являются: проведённое совещание, наступившая дата гейта, наличие документа, успешный прогон CI, согласие в переписке. Всё это — условия для рассмотрения. Решение существует только как явно записанный выбор из GO, REWORK, STOP (и RETIRE — только для `GATE-05`), сделанный носителем ответственной роли.

По `RULE-AI-001` ИИ вправе готовить материалы к гейту и проверять предъявленные доказательства, но решение по гейту не принимает ни в каком виде. Отсюда три запрета, действующих для любого навыка:

- навык **не предлагает** решение и **не рекомендует** его — даже когда допустимо ровно одно;
- навык записывает решение **только после явной реплики** носителя ответственной роли в форме «решение: GO», «решение: REWORK», «решение: STOP». Реплики «согласен», «идём дальше», «ок», «ну давай» решением не являются: навык называет требуемую форму и ждёт её;
- пока явной реплики не было, `document_status` — «проект решения», и поле `decision` в документе **отсутствует целиком**, а не стоит пустым или предположительным значением.

Решение и заключение — разные документы разных ролей. Заключение роли метки GO, REWORK, STOP не несёт ни в каком поле (см. `gate-conclusion.md`).

## Допустимость решения GO

Допустимость вычисляется механически, до и независимо от решения, и показывается носителю роли до того, как он назовёт своё решение.

`GO` недопустимо, если верно хотя бы одно:

- не получено хотя бы одно обязательное заключение роли из состава этого гейта (`roles-gates.md`, таблица «Этапы и гейты»);
- в каком-либо из полученных заключений есть замечание с `blocking: true`;
- есть неразрешённая терминологическая или нормативная коллизия.

На допустимость отсутствие рекомендательного заключения не влияет, и в причины оно не попадает (см. `roles-gates.md`, «Независимая проверка: рекомендательная роль»).

Недопустимость GO не предрешает, каким будет решение: REWORK и STOP допустимы всегда. Если носитель роли называет «решение: GO» при `go_admissible: false`, навык решение не записывает, перечисляет причины недопустимости и ждёт либо другого решения, либо снятия причин — нового заключения, закрытого вопроса. Спорить о существе причин навык не вправе: причина снимается изменением материала, а не согласием.

## Машинная проекция (gate-decision.yaml)

### Верхнеуровневые поля

| Поле | Назначение |
|---|---|
| `product_id` | Идентификатор продукта — тот же, что в `description.yaml`. |
| `gate` | Код гейта (`GATE-01` … `GATE-06`). |
| `responsible_role` | Код ответственной роли гейта — берётся из `roles-gates.md`, а не со слов пользователя. |
| `holder` | Носитель ответственной роли — из `roles_declared` приложенного описания; «не назначена» либо «не назван», если в `roles_declared` роль не занята или не упомянута. |
| `date` | Дата решения. |
| `document_status` | «проект решения» либо «решение записано». |
| `decision` | `GO`, `REWORK` или `STOP`; `RETIRE` — только при `gate: GATE-05`. Поле отсутствует целиком, пока `document_status` — «проект решения». |
| `role_combination_note` | Строка о совмещении ролей; поле отсутствует, если совмещения нет. |
| `rationale` | Решение своими словами ответственной роли: почему именно так. Присутствует только при записанном решении; формулировкой ИИ не заполняется. |
| `process_references` | Ссылки на процессную опору — те же поля, что в `description-schema.md`. |

### Массив `conclusions`

Перечень заключений, на которые опирается решение. Строка есть **для каждой роли обязательного заключения этого гейта** по `roles-gates.md` — независимо от того, получено заключение или нет.

| Поле | Назначение |
|---|---|
| `role` | Код роли. |
| `holder` | Носитель роли из `roles_declared`. |
| `verdict` | Вердикт из заключения (три значения `gate-conclusion.md`) либо «не получено», если заключения нет. |
| `file` | Путь к файлу заключения; отсутствует, если заключение не получено. |

Рекомендательные заключения в массив попадают только тогда, когда они фактически получены: строка «не получено» для рекомендательной роли не заводится — её отсутствие решению не препятствует и причиной недопустимости не является.

### Объект `admissibility`

| Поле | Назначение |
|---|---|
| `go_admissible` | `true` либо `false`. Вычисляется по правилам выше, а не назначается. |
| `reasons` | Список причин недопустимости, каждая — строка, называющая конкретный адрес: «не получено обязательное заключение ROLE-…», «блокирующее замечание F-… в заключении ROLE-…», «неразрешённая терминологическая коллизия OQ-…». При `go_admissible: true` список пуст. |

### Массив `evidence`

Доказательства, на которые опирается решение, — со слов носителя роли, ссылками. Каждый элемент: `id`, `text` (что это за доказательство), `link` (ссылка на внутреннее хранилище; содержимое не копируется — то же правило, что для `attachments` в `description-schema.md`). Навык доказательства не выдумывает и не выводит из материала: если их не назвали, массив пуст, и это видно.

## Человеческая проекция (decision.md)

Документ открывается шапкой: продукт, гейт, ответственная роль и её носитель, дата, статус документа. Если есть совмещение ролей — строка о совмещении, без оценки.

Дальше — заключения перечнем, строками вида «роль — носитель — вердикт — файл»; таблиц здесь нет, потому что перечень читают глазами на гейте, а не сравнивают по колонкам. Неполученные заключения перечисляются наравне с полученными, со словом «не получено».

Дальше — допустимость: одной строкой «GO допустимо» или «GO недопустимо», и при недопустимости — причины списком.

Дальше — решение и обоснование. Пока решение не записано, здесь стоит строка о том, что документ является проектом решения и решения не содержит.

Документ заканчивается фразой о том, что решение по гейту относится к процессу разработки и соответствия внешнему стандарту не означает: гейт пройден по правилам этого процесса, и ничего сверх этого утверждать нельзя.

## Файлы и хранение

Шаблон решения — `shared/templates/gate-decision-template.md` и `.yaml`.

Имена постоянные: `docs/product/<product-id>/gates/<GATE-NN>/decision.md` и `.yaml`. Сохранение файлов выполняет носитель ответственной роли сам; навык называет путь и выдаёт содержимое, но не утверждает, что файл сохранён.
