# История версий

## 0.11.5

Условия ролей — решение ROLE-PROCESS-OWNER от 2026-10-01 (Q-107): роль может дополнять
правила Конституции собственными условиями в пределах своих полномочий; разрешено всё, что
явно не запрещено и не задекларировано Конституцией; утверждает ROLE-AI-USE-CASE-OWNER
решением GO.

- Правило протокола R14: навык применяет утверждённые условия активной роли из
  `references/role-conditions.yaml` в режимах из их `applies_to` и называет их одной строкой.
  Конституция выше условий, условия выше умолчаний навыка — шагов режимов, шаблонов и правил
  протокола, кроме трёх: ИИ не принимает решений (R4), исключение данных (R7), работа без
  подгрузки материалов. Реестр добавлен в основания R1; до выхода версии с записью можно
  приложить запись с GO в сеансе. Нет условий — работа как раньше.
- Режим «Предложить условие роли» во всех навыках: PO-8, FA-13, TA-9, а для ролей без своего
  навыка — G-4. Навык сверяет условие с Конституцией и выдаёт готовую запись для реестра.
- Условия перехода через гейт: G-1 проверяет условия ролей для гейта; невыполненное или
  без данных — блокирующий пункт как отсутствие доказательства (раздел 3.1); условие,
  требующее суждения роли, уходит вопросом в её заключение.
- Реестр `role-conditions.yaml` в общих справочниках; нормативная проверка `role_conditions`
  проверяет каждую запись: действующая роль, свои режимы, существующие гейты, модуль только
  у функционального архитектора, GO владельца применения ИИ с цитатой и датой, нет
  блокирующих формулировок.

## 0.11.4

Сначала общая картина, потом детали — решение ROLE-PROCESS-OWNER от 2026-09-30 (Q-106). Повод:
функциональный архитектор получал проработку кусками и список объектов на 25 строк «на
подтверждение».

- Новое правило протокола R13 для всех четырёх навыков: первый содержательный ответ режима —
  карта на одном экране (схема Mermaid и короткая таблица), затем детализация по одному блоку
  со строкой «Где мы:». Уровень согласуется целиком; перечень длиннее 7 пунктов на
  подтверждение не выносится; за ответ — не больше 3 развилок с вариантами и рекомендацией;
  остальное — помеченные предположения. Полный артефакт — по слову «собери».
- Формат ответа облегчён: «Основания», «Пробелы», «Требует утверждения» выводятся, только
  когда в них есть содержание; во время проработки — строка «Предположений: N · Открытых
  вопросов: M» и развилки «Решить:».
- FA-1 проходит модуль уровнями: карта модуля → блоки → сквозные разделы; содержание
  перечня TERM-FUNCTIONAL-ARCHITECTURE сохранено полностью. Макеты экранов функциональный
  архитектор предлагает сам при детализации блока; FA-3 начинается с карты экранов, FA-7 — с
  хребта сценария. Термины сверяются раз на уровень, а не после каждого раздела.
- PO-1 начинается с карты продукта; TA-1 — с сути решения, TA-2 — с контекста системы, TA-3
  — с карты развёртывания, TA-5 — с карты обменов; пакет гейта G-1 — с итога на один экран.
- Шаблоны: в `functional-architecture` добавлены разделы «Карта модуля», «Предположения»,
  «Открытые вопросы», в `product-description` — «Карта продукта», «Предположения», «Открытые
  вопросы». Схемы артефактов не ослаблены: обязательные поля проверяются при сборке.
- Проверка S-07 охватывает и R13.

## 0.11.2

Документация и навыки сверены с поведением 0.11.1 и с платформой; найденные расхождения
устранены.

- Навыки больше не называют основанием «только опубликованные действующие редакции»: основание
  — встроенные извлечения Конституции 0.9 и Регламента приёмки 0.1 (черновики), остальное —
  если доступно (правило R1). При отсутствии опубликованных условий применения ИИ — работа с
  отметкой в `ai_assistance.gaps` прямо в разделе «Протокол сеанса» каждого навыка.
- Проверка терминов в шагах режимов (PO-1, FA-6, раздел FA «Режимы», проверка «Перед
  выдачей») получила запасной путь: без реестра `sigma_terms` — приложение A встроенной
  Конституции. Раньше чек-лист FA требовал «проверен через реестр», и без реестра найденные
  термины понижались до `TERM_NOT_DEFINED`.
- PO-1: ответы сначала берутся из беседы и приложенных материалов, вопросы задаются только
  недостающие (правило R11).
- R12 в разделах навыков: предупреждение только для модуля СИГМА.MES+ вне M01–M13; об
  отдельном продукте или сервисе пользователя навык не предупреждает.
- Карточка плагина: описание говорит, что Конституция и Регламент встроены и ничего
  подгружать не нужно; стартовых подсказок три — больше Codex не принимает, и четвёртая
  («Подготовить пакет гейта») отбрасывалась (Q-105).
- Установка: реальный адрес маркетплейса вместо заполнителя, перезапуск приложения и новый
  чат, раздел «Обновление» (`codex plugin marketplace upgrade sigma-mes`; кто ставил 0.11.0,
  обновляется обязательно), способы вызвать навык, требование Codex CLI 0.146.0+. Расширение
  IDE плагины не поддерживает — сказано прямо, дан способ подключить навыки копированием.
- README, OPEN-QUESTIONS (Q-04, Q-06, Q-08, дословное решение в Q-103, новые Q-104 о
  лицензии и Q-105), покрытие сценариев (T-02, T-08, T-10, T-14, T-18) приведены к
  фактическому поведению.

## 0.11.1

Плагин стал полностью самодостаточным — решение ROLE-PROCESS-OWNER от 2026-09-29 (Q-103).

- Протокол сеанса больше ничего не требует от пользователя. Ни один шаг S1–S6 не
  останавливает работу: без доступа к файлам артефакт выдаётся в ответе, без
  `sigma-mes.config.yaml` навык работает без него, основание — встроенные извлечения
  Конституции 0.9 и Регламента приёмки 0.1, без опубликованных условий применения ИИ и без
  реестра терминов работа продолжается с отметкой в артефакте.
- Новое правило R11: материалы пользователя — описание сервиса, «Конституция сервиса»,
  заметки, прежние артефакты — принимаются на вход, из них берутся ответы.
- Новое правило R12: модуль вне состава M01–M13 не блокирует работу — одна строка
  предупреждения, что модуль не входит в Конституцию, и работа в полном объёме. Нужно для
  проработки идей и гипотез масштабирования.
- Отдельный продукт — не новый модуль: функциональная и техническая архитектура
  применяются к любому развиваемому продукту (RULE-PRODUCT-FRAME-002), предупреждения
  о составе M01–M13 для него нет.
- Без реестра терминов термины сверяются с приложением A встроенной Конституции: найденный
  термин — `TERM_PASS` с отметкой о непроверенном по реестру статусе; решение, зависящее от
  критичного термина без определения, — проект до утверждения термина (RULE-TERM-001).
- `sigma-mes.config.yaml` может быть заполнен частично: заполненные пути используются,
  незаполненные пропускаются, а артефакт для незаполненного пути выдаётся в ответе.
- Опубликованные условия применения ИИ соблюдаются; расхождение версии инструкции — одна
  строка и отметка о повторном разрешении по RULE-AI-001, работа не останавливается.
- Данные вне условий не переносятся ни в ответ, ни в артефакт; без опубликованных условий
  исключаются как минимум персональные данные, секреты и ключи, договорные документы
  заказчиков.
- Пакет гейта: заключения ищутся и в материалах пользователя; `present: true` — только при
  найденном тексте заключения. Навык гейтов работает в ролях 1–3 без переадресации, когда
  они ответственные за гейт.
- Функциональная приёмка без PASS и описания разработчика готовится как проект; исход по
  RULE-ACCEPTANCE-004 не предлагается до появления обеих предпосылок. Шаблон приёмки больше
  не содержит поля исхода: его добавляют только при наличии обеих предпосылок.
- FA-9, шаг 0: расхождение версии опубликованного Регламента приёмки со встроенной 0.1 —
  одна строка и отметка в `ai_assistance.gaps`, запись приёмки готовится. PO-2: выход за
  границы продукта больше не переводит в PO-6 вместо работы.
- Формат артефактов: `ai_assistance.plugin_version` — версия плагина, схемы принимают
  только её; артефакт прежней версии при доработке получает новую. В пакете гейта при
  `present: true` обязателен непустой `ref`. Шаблоны не содержат полей, требуемых только по
  условию: `outcome` и `after_rejection_decision` в `acceptance-record`, `reviewer_result`
  в `role-conclusion` (только для ROLE-INDEPENDENT-REVIEWER).
- Проверка S-07 охраняет самодостаточность: блокирующая формулировка в протоколе сеанса
  (шаги S1–S6 и правила R1–R12), в шаблоне конфигурации и в разделе «Протокол сеанса»
  каждого навыка — ошибка приёмки.
