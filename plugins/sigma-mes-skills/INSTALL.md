# Установка sigma-mes-skills 0.11.4

Плагин самодостаточен: Конституция разработки 0.9, Регламент функциональной приёмки 0.1,
коды, схемы и шаблоны артефактов лежат внутри него. Установили — можно работать. Никаких
файлов подгружать и ничего настраивать для начала работы не нужно.

## 1. Требования

- ChatGPT для десктопа: плагин устанавливается в режимах Codex или Work; навыки доступны в
  новых чатах, в том числе в обычном режиме чата и в проекте чата.
- Или Codex CLI 0.146.0 и новее: с этой версии поддерживаются манифесты Agent Plugins.
  Проверить версию: `codex --version`.

Без доступа к рабочему репозиторию навык выдаёт артефакты целиком в ответе, сохраняете их вы.

Расширение Codex для IDE плагины не поддерживает. Там навыки подключаются без плагина:
скопируйте каталоги `plugins/sigma-mes-skills/skills/<навык>/` целиком в `.agents/skills/`
рабочего репозитория или в `~/.agents/skills/`. Каждый навык несёт свою копию справочников в
`references/` и работает сам по себе.

## 2. Подключение маркетплейса и установка

```
codex plugin marketplace add petrovich-opendev/sigma-mes-methodology
```

То же полным адресом: `https://github.com/petrovich-opendev/sigma-mes-methodology.git`.
Закрепить конкретный выпуск можно ключом `--ref v0.11.4`, но тогда обновление (раздел 3)
новую версию не подтянет. Постоянное место хранения плагина определяет ROLE-PROCESS-OWNER
(OPEN-QUESTIONS.md, Q-04); при переезде адрес здесь будет заменён.

Установка:

- **ChatGPT для десктопа.** После добавления маркетплейса перезапустите приложение. В режиме
  Codex или Work откройте Plugins Directory, выберите источник «СИГМА.MES+» и установите
  `sigma-mes-skills`. Без Codex CLI: склонируйте репозиторий и откройте его в режиме Codex —
  приложение читает маркетплейс репозитория из `.agents/plugins/marketplace.json`.
- **Codex CLI.** `/plugins` → источник «СИГМА.MES+» → `sigma-mes-skills` → установить.

Навыки появляются в новом чате или новом сеансе Codex CLI.

## 3. Обновление

Если маркетплейс подключён командой `codex plugin marketplace add`:

```
codex plugin marketplace upgrade sigma-mes
```

Если плагин установлен из клона репозитория (без Codex CLI) — выполните `git pull` в клоне.

Затем перезапустите ChatGPT для десктопа или начните новый сеанс Codex CLI. Кто ставил
0.11.0, обновиться обязательно: та версия требовала конфигурацию и опубликованные документы
и останавливала работу. Если после обновления навык всё ещё просит подгрузить материалы,
удалите плагин и установите его заново.

## 4. Начало работы

Навыков четыре: `sigma-product-owner`, `sigma-functional-architect`,
`sigma-technical-architect`, `sigma-gates`. Вызвать навык:

- в ChatGPT — набрать `@` и выбрать плагин или навык, либо нажать стартовую подсказку в
  карточке плагина;
- в Codex CLI — `$sigma-product-owner` (и так далее) или `/skills`;
- везде можно просто описать задачу: навык подберётся по описанию.

Навык покажет список ролей и попросит выбрать; дальше работа идёт сверху вниз: сначала карта
на одном экране (схема и таблица), которую согласуют целиком, потом детализация по одному
блоку. Полный артефакт навык собирает по слову «собери», полную карту показывает по слову
«карта». Каждый ответ начинается строкой
`Активная роль: …`. Прикладывайте любые свои материалы — описание сервиса, заметки, выгрузки,
прежние артефакты: навык берёт из них ответы и не переспрашивает то, что там уже есть.

Модуль СИГМА.MES+ вне состава M01–M13 — не препятствие: навык одной строкой предупредит, что
модуль не входит в Конституцию, и продолжит работу. Это предусмотрено для проработки идей и
гипотез масштабирования. Отдельный продукт или сервис — не новый модуль, о нём навык не
предупреждает.

## 5. Необязательно: реестр терминов

Без реестра навык сверяет термины с приложением A встроенной Конституции. Если в вашей среде
есть MCP-сервер реестра терминов, его можно подключить в `~/.codex/config.toml`:

```toml
[mcp_servers.sigma_terms]
url = "<HTTPS-адрес MCP реестра терминов>"        # сообщает ROLE-DOCUMENTATION-OWNER
bearer_token_env_var = "SIGMA_TERMS_TOKEN"        # токен хранится только в переменной окружения
default_tools_approval_mode = "writes"            # инструменты не только для чтения требуют подтверждения
required = false
```

Список инструментов посмотреть командой `/mcp` и оставить в `enabled_tools` только
инструменты чтения. Запрещено записывать токен в файлы репозитория.

## 6. Необязательно: сохранение в рабочий репозиторий

Работает там, где у навыка есть доступ к файлам рабочего репозитория. Если хотите, чтобы
навык сам сохранял артефакты в репозиторий документации и сверял встроенную Конституцию с
опубликованной, скопируйте шаблон `plugin-src/shared/config-template.yaml` из репозитория
плагина (та же копия лежит в `skills/<навык>/references/config-template.yaml`) в корень
рабочего репозитория как `sigma-mes.config.yaml` и заполните нужные пути. Можно попросить
навык показать шаблон. Незаполненные пути навык просто пропускает: работа от этого не
останавливается.

## 7. Условия применения ИИ

RULE-AI-001 требует, чтобы ИИ применялся в условиях, разрешённых ROLE-AI-USE-CASE-OWNER.
Если условия опубликованы и путь к ним задан в `sigma-mes.config.yaml`
(`paths.ai_use_conditions`), навык их соблюдает. Если нет — навык работает, а в каждом
артефакте отмечает, что он подготовлен без утверждённых условий: такой материал — проект,
его утверждает профильная роль.
