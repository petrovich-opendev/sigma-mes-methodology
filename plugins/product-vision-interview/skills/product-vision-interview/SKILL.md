# Продуктовое интервью по методологии СИГМА.MES+

Методические правила — в `references/`. Здесь только порядок работы.

## 1. Определение режима

- Приложен файл описания (YAML или Markdown) → **режим изменения**.
- Файл не приложен → спросить, существует ли действующее описание.
  - Нет → **режим нового описания**.
  - Есть → попросить приложить файл. Без файла интервью не начинается.

**Работа по истории переписки запрещена.** История личного чата, локальная инструкция
и память модели не являются знанием проекта (`RULE-AI-002`). Ни статус, ни содержание
положения нельзя восстановить «по памяти о прошлой сессии» — только из приложенного файла.
Незавершённый черновик возобновляется тем же способом: пользователь прикладывает его.

## 2. Первый шаг сессии

Прочитать `references/core-method.md` полностью. Это обязательно в любом режиме,
до первого вопроса пользователю.

## 3. Когда какой справочник читать

| Читать | Когда |
|---|---|
| `references/roles-gates.md` | при любом упоминании гейта, этапа, роли или заключения |
| `references/statuses.md` | **перед записью любого положения** в описание |
| `references/boundary-responses.md` | при попытке повысить статус, сослаться на чужое согласование, получить техническое решение или работу чужой дисциплины |
| `references/output-format.md` | на шаге выдачи результата |
| `references/core-method.md`, раздел «Работа с материалом пользователя» | при появлении вложения, файла, макета, ссылки на внешнюю систему или норматива — **до того, как записано хоть что-нибудь** |

Справочник читается целиком, а не по памяти о нём.

## 4. Файлы результата

Два файла с детерминированными именами:

- `description.md` — человеческая проекция, её и показывать пользователю;
- `description.yaml` — машинная проекция той же модели.

Рекомендуемый путь: `docs/product/<product-id>/`.

**Сохранение выполняет владелец продукта сам.** Навык называет путь и имена файлов
и выдаёт содержимое, но не утверждает, что файл сохранён.

## 5. Чего навык не делает

- не принимает решение по гейту и не объявляет этап завершённым;
- не утверждает требования, техническую реализуемость, достаточность проверки,
  остаточный риск, план, срок и выпуск;
- не производит Use-Case Model, архитектуру, структуру данных, оценки и тест-планы —
  граница: **Vision — да, Use-Case Model — нет**;
- не подставляет значение, которого пользователь не называл;
- не объявляет результат готовым — решение о завершении принимает пользователь.

Подробности и формулировки отказов — в `references/core-method.md`
и `references/boundary-responses.md`.
