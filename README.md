# sigma-mes-methodology

Публичный маркетплейс плагинов Claude Code. В репозитории один плагин —
`sigma-mes-skills`, внутри которого живут навыки ролей процесса СИГМА.MES+.
Правило упаковки: **один навык — одна роль**, роли не объединяются ни в одном
навыке. Сейчас навыков два:

- **`product-vision-interview`** — владелец продукта (`ROLE-PRODUCT-OWNER`):
  продуктовое описание как вход к GATE-01 и запись решения по GATE-01;
- **`domain-model-interview`** — функциональный владелец (`ROLE-FUNCTIONAL-OWNER`):
  предметная модель по продуктовому описанию, словарь функциональной области,
  заключение к GATE-01, обзор практик по функциональному дизайну и концепт
  интерфейса — пять режимов.

Из тех же исходников скрипт `build/build.sh <навык>` собирает платформонезависимую
инструкцию `build/<навык>/chatgpt-instructions.md` — тот же метод, годный для чата
ChatGPT без установки плагина. Сборка делается на роль: один файл на один навык,
общей сборки на несколько ролей нет и не будет.

## Для кого

Каждый навык рассчитан на диалог с одной ролью и не подменяет собой другие роли
процесса: `product-vision-interview` — с владельцем продукта,
`domain-model-interview` — с функциональным владельцем. Там, где вопрос выходит
за границу роли, навык отказывает и называет код роли, которой вопрос адресован.

## Что делает продуктовый навык

Ведёт структурированное интервью с владельцем продукта и переводит
первоначальную идею в продуктовую часть Vision — `description.md` (для
чтения) и `description.yaml` (машинная проекция той же модели). Работа
опирается на дерево продуктовых решений: один вопрос за ход, виден остаток
существенных вопросов, каждое положение размечено по трём осям (тип
содержания, статус подтверждения, адресат заключения) и по автору
формулировки. Подробности метода — в `references/core-method.md`.

## Что делает навык функционального владельца

Разворачивает уже принятые продуктовые решения в предметную модель — `domain.md`
и `domain.yaml`: критичные производственные объекты, их состояния и основания
признания, предметные правила, сквозной производственный сценарий на уровне
последовательности и границ, словарь функциональной области. Отдельным режимом
готовит заключение функционального владельца к GATE-01 по чек-листу из шести
проверок. Продуктовое описание навык не меняет никогда: найденное расхождение
уходит запросом владельцу продукта. Подробности — в `references/domain-method.md`.

**Граница навыка одной фразой: смысл объектов, их жизненный цикл и то, что где
стоит на экране, — да; способ хранения и то, как это выглядит, — нет.**

## Чего продуктовый навык не делает

- не принимает решение по гейту и не объявляет этап или интервью завершённым;
- не утверждает требования, техническую реализуемость, достаточность
  проверки, остаточный риск, план, срок или выпуск;
- не подставляет правдоподобное значение вместо неизвестного и не
  восстанавливает статус или содержание по памяти о прошлой сессии;
- не даёт положению большего статуса, чем позволяют правила разметки
  (см. `references/statuses.md`), под давлением собеседника;
- не выполняет работу другой дисциплины и другой роли — архитектуры,
  тестирования, планирования поставки, требований;
- не сохраняет файлы результата на диск и в git — это делает владелец
  продукта сам;
- не производит макеты интерфейса и не переносит в описание состав
  экранных форм: концепт интерфейса ведёт `ROLE-FUNCTIONAL-OWNER`, макет в
  границах концепта делает `ROLE-DEVELOPER`.

**Граница навыка одной фразой: Vision — да, Use-Case Model — нет.**

## Структура репозитория

```
.claude-plugin/marketplace.json          — описание маркетплейса
plugins/sigma-mes-skills/                — плагин навыков ролей
  .claude-plugin/plugin.json
  shared/references/                     — общие справочники, хранятся один раз
    roles-gates.md                       — этапы, гейты, перечень ролей
    statuses.md                          — разметка по трём осям
    terms-registry.md                    — критичные термины Конституции
    description-schema.md                — схема description.yaml
    domain-schema.md                     — схема domain.yaml
    gate-conclusion.md                   — формат заключения роли к гейту
    gate-decision.md                     — формат записи решения по гейту
    role-answer.md                       — формат ответа роли на запрос и на вопрос
    research-schema.md                   — схема research.yaml: обзор практик
    screens-schema.md                    — схема screens.yaml: концепт интерфейса
    incoming-documents.md                — приём ответов и заключений в режиме изменения
    architect-handoff.md                 — передача материалов архитектору
  shared/templates/                      — формы для ролей, у которых навыка нет
    gate-conclusion-template.md/.yaml
    gate-decision-template.md/.yaml
    role-answer-template.md/.yaml
    architect-handoff-template.md/.yaml
  skills/
    product-vision-interview/            — роль ROLE-PRODUCT-OWNER
      SKILL.md, references/, examples/, templates/, build/
    domain-model-interview/              — роль ROLE-FUNCTIONAL-OWNER
      SKILL.md, references/, examples/, templates/, build/
build/
  build.sh                               — сборка инструкции на один навык
  sync-shared.sh                         — раскладка общих справочников по навыкам
  check.sh                               — копии не разошлись с источником
  product-vision-interview/chatgpt-instructions.md
  domain-model-interview/chatgpt-instructions.md
tests/
  shared/structure.md                    — семь проверок структуры репозитория
  product-vision-interview/
    scenarios.md                         — тридцать пять сценариев проверки
    expected-behaviour.md                — ожидаемое поведение и метрики прогона
  domain-model-interview/
    scenarios.md                         — тридцать шесть сценариев проверки
    expected-behaviour.md                — ожидаемое поведение
docs/
  new-skill-checklist.md                 — что обязан соблюдать новый навык
  gate01-checklist-pm.md                 — что проверяет руководитель проекта к GATE-01
INSTALL.md                               — пути установки и переход между версиями
README.md                                — этот файл
OPEN-QUESTIONS.md                        — открытые вопросы методики и схемы
```

В каждом навыке `references/` содержит его собственные справочники и копии общих,
сгенерированные `build/sync-shared.sh`. Копии помечены первой строкой
«СГЕНЕРИРОВАНО» и руками не правятся: правка вносится в `shared/references/`.

Формы гейтовых документов лежат в `shared/templates/` и по навыкам не копируются:
заключение к гейту даёт любая роль, а не только та, у которой есть навык. Как
работать без навыка — в [INSTALL.md](INSTALL.md), раздел «Роль без навыка».

## Установка

```
/plugin marketplace add petrovich-opendev/sigma-mes-methodology
/plugin install sigma-mes-skills@sigma-mes-methodology
```

Плагин ставится целиком; оба навыка подключаются вместе с ним. Подробности,
включая установку вне Claude Code (через `build/<навык>/chatgpt-instructions.md`),
переход с прежних версий и обновление плагина — в [INSTALL.md](INSTALL.md).

## Статус

v0.10.0 — обзор практик и концепт интерфейса у функционального владельца.

- **исследование практик**: дерево вопросов, каждый привязан к объекту или шагу сценария
  (к зоне или экрану — только когда концепт уже собран) — вопрос без привязки не
  принимается; по вопросу два-четыре кандидата,
  никогда один; у каждого происхождение и проверка, и кандидат из знания навыка
  подтверждённым стать не может; решение записывается только по явному выбору владельца;
- **концепт интерфейса**: зоны оболочки и содержание зон из объектов модели; концепт
  объектов не заводит, а всё, чего в модели нет, уходит в `unbound` с адресацией;
  после каждого изменения оболочки — текстовый каркас экрана, без картинок и SVG;
- уровни точности разведены: зоны, объекты, состояния и действия — функциональный
  владелец; размеры, цвета и поведение элементов — `ROLE-DEVELOPER` в границах концепта;
- закрыт открытый вопрос 10: концепт — `ROLE-FUNCTIONAL-OWNER`, макет —
  `ROLE-DEVELOPER`, согласование обоих — с `ROLE-ARCHITECT` совместно.

Ранее: v0.9.0 — замкнутый рабочий цикл двух ролей до передачи архитектору.

- **контур замкнулся**: ответ роли приходит файлом и переводит положение в «ответ
  роли зафиксирован» с источником из ответа; решение REWORK разбирается по находкам
  заключения — каждая закрывается изменением либо мотивированным отказом, состояние
  видно в `findings_state`; изменение разделов 5–7 автоматически порождает запрос
  функциональному владельцу;
- **передача архитектору**: пятый режим продуктового навыка собирает комплект
  Инициации, сводит вопросы к архитектору из всех документов Инициации и механически проверяет
  три условия готовности; невыполненное условие записывается, а не скрывается;
- **интервью**: четвёртый обязательный вопрос — один путь от основания до результата,
  который функциональный владелец берёт напрямую по полю `scenario_step`; три вопроса
  на каждый риск — что он запускает, по какому раннему признаку его заметят, чья это
  зона;
- эталонный пример полного цикла на пилотном продукте: REWORK → доработка → ответ
  архитектора → повторное заключение → GO → передача.

Ранее: v0.8.0 — сверка терминов, формы для ролей без навыка, зафиксированные расхождения
с Конституцией v0.8.

- значимые слова положений сверяются с реестром критичных терминов: три исхода —
  `TERM_PASS` молча, `TERM_AMBIGUOUS` с открытым вопросом и потолком статуса,
  отсутствие в реестре как термин функциональной области. Сверка портируема:
  реестр — файл, внешних сервисов не требуется;
- `shared/templates/` — формы заключения к гейту, записи решения и ответа роли на
  запрос; раздел «Роль без навыка» в INSTALL и чек-лист руководителя проекта к
  GATE-01 в `docs/`;
- `scope`, `owner_role` и `source` в записи термина обязательны: кандидат без
  области и владельца никому не адресован;
- открытые вопросы 15 и 16 — расхождения правил навыка с редакцией v0.8 по
  независимой проверке и требованиям к качеству; правила навыка не менялись.

Ранее: v0.7.0 — второй навык: функциональный владелец.

- навык `domain-model-interview` — предметная модель по продуктовому описанию,
  словарь функциональной области и заключение к GATE-01 по чек-листу из шести
  проверок;
- статус оси 2 «утверждено владельцем продукта» обобщён до «утверждено
  ответственной ролью» с обязательным полем `approved_by`: одно значение с полем
  роли масштабируется на любое число навыков;
- терминологический контракт: `terms-registry.md` с критичными терминами
  Конституции, расширенная запись `term_candidates`, поле `terms` у положений;
- справочники переведены на редакцию Конституции v0.8, перечень ролей дополнен
  до шестнадцати; состав гейтов не менялся;
- общие форматы `gate-conclusion.md` и `gate-decision.md`: заключение роли —
  вход для решения и меток GO/REWORK/STOP не несёт; решение по гейту
  записывается только явной репликой человека и только при допустимости;
- в продуктовом навыке появился четвёртый режим — решение по GATE-01;
- открытые вопросы 11–14.

Ранее: v0.5.0 — структурная версия, содержание методики без изменений: несколько
навыков в одном плагине, общие справочники, сборка на роль, версия в первой
реплике. v0.4.0 — работа над ошибками по итогам реального прогона:

- шапка документа и роли собираются отдельным шагом в начале сессии, а не
  остаются плейсхолдерами;
- на завершении добавлены два шага: явное утверждение разделов владельцем
  продукта и предложение переписать формулировки ИИ своими словами;
- пример проверки, вводящий новую функцию, до решения о границе в описание
  не попадает;
- потолки статуса подтверждения заданы по разделам, а «принято к
  формулировке» стало седьмым официальным значением оси 2;
- введён инвариант связи «положение ↔ запрос роли»;
- для продуктов вне модульной схемы допустимо значение модуля «вне схемы
  M01–M13» с одним открытым вопросом на документ;
- в описании появился блок «Состояние для GATE-01».

Ещё раньше: v0.3.0 — независимая проверка (ROLE-INDEPENDENT-REVIEWER)
переведена из обязательных заключений в рекомендательные; v0.2.0 — правила
приёма материала пользователя (макеты, файлы, числа, нормативы, интеграции,
приоритет ролей, конфликт с ранее записанным).
Процессная опора — Конституция СИГМА.MES+ v0.8 (ШАБЛОН, `draft_template`,
нормативные поля не заполнены); `full_conformance_claim = false` — заявления о полном
соответствии OpenUP не делается.

Открытые вопросы методики и схемы — в [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md).
