# Методика СИГМА.MES+: плагин ролей и гейтов

Репозиторий содержит плагин `sigma-mes-skills` версии 0.11.5 — навыки ролей Конституции
разработки СИГМА.MES+ и правила гейтов. Плагин готовит материалы ролей и пакеты гейтов по
встроенным в него дословным текстам Конституции и Регламента приёмки.

**Плагин самодостаточен.** Всё нормативное он везёт с собой: установили — работаете, без
подгрузки документов, конфигурации и подключения сервисов. Материалы пользователя навык
принимает на вход. Модуль вне состава M01–M13 не блокирует работу — только одна строка
предупреждения.

**ИИ не принимает решений** (RULE-AI-001). Термин и его статус, включение требования, исход
функциональной приёмки, решение по гейту, остаточный риск и выпуск записываются только как
дословная цитата реплики человека в соответствующей роли. Без такой реплики поле остаётся
незаполненным.

**Сначала общая картина, потом детали.** Каждый режим навыка начинает с карты на одном экране — схема Mermaid и короткая таблица, — а затем детализирует по одному блоку. Согласуются уровни целиком, а не строки: перечни длиннее 7 пунктов на подтверждение не выносятся, за ответ — не больше 3 развилок с вариантами и рекомендацией, остальное — помеченные предположения. Функциональный архитектор сам предлагает макеты экранов, когда детализирует блок.

## Основание

- Конституция разработки СИГМА.MES+ редакции **0.9** (черновик).
- Регламент функциональной приёмки редакции **0.1** (черновик).

Дословные извлечения обоих документов лежат в плагине и служат основанием для ролей, правил
и гейтов. Значения терминов берутся из реестра терминов, если он подключён, иначе — из
приложения A встроенной Конституции. Пересказов нет.

## Среда исполнения

- ChatGPT для десктопа: плагин устанавливается в режимах Codex или Work, навыки доступны в
  новых чатах, включая обычный режим чата и проект в чате;
- Codex CLI 0.146.0 или новее.

Расширение Codex для IDE плагины не поддерживает; там навыки можно подключить без плагина —
см. `plugins/sigma-mes-skills/INSTALL.md`.

Доступ к файлам рабочего репозитория необязателен: без него навык выдаёт артефакты целиком
в ответе. С ним — может сохранять их сам и сверять встроенную Конституцию с опубликованной,
если в репозитории есть `sigma-mes.config.yaml`.

## Навыки

Принцип «один навык — одна роль»; навык гейтов общий.

- **`sigma-product-owner`** — ROLE-PRODUCT-OWNER. Описание продукта, развитие работающего
  продукта, разногласия функциональных архитекторов, варианты для предприятий, ответственный
  за общие элементы функциональной архитектуры, предложение об изменении Конституции,
  заключение к гейту. Режимы PO-1…PO-7.
- **`sigma-functional-architect`** — ROLE-FUNCTIONAL-ARCHITECT. Функциональная архитектура
  модуля, исследование практик, концепт интерфейса и макеты, функциональные требования,
  требования к качеству, предметные термины, сквозные сценарии, тест-дизайн, функциональная
  приёмка, изменение функциональной архитектуры, журнал вопросов. Режимы FA-1…FA-12.
- **`sigma-technical-architect`** — ROLE-TECHNICAL-ARCHITECT. Технические архитектурные
  решения (ADR), модель C4 на Structurizr DSL, архитектура развёртывания с откатом,
  обеспечение требований к качеству, интеграционная архитектура, проверка отнесения функций
  к модулям, технические термины. Режимы TA-1…TA-8.
- **`sigma-gates`** — правила гейтов GATE-01…GATE-06. Пакет гейта с блокирующими пунктами,
  формы заключений ролей без собственного навыка, запись решения ответственной роли.
  Режимы G-1…G-3.

## Структура репозитория

```
.agents/plugins/marketplace.json          — маркетплейс репозитория
plugin-src/shared/                        — единый источник общих справочников
  session-protocol.md                     — протокол сеанса: шаги S1–S6, правила R1–R14
  constitution.extract.yaml               — дословное извлечение Конституции 0.9
  acceptance-regulation.extract.yaml      — дословное извлечение Регламента приёмки 0.1
  codes.yaml                              — разрешённые коды и версии, для которых собран плагин
  deprecated.yaml                         — выведенные из употребления коды с заменами
  config-template.yaml                    — шаблон sigma-mes.config.yaml рабочего репозитория
  role-conditions.yaml                    — реестр утверждённых условий ролей (R14)
  artifact-schemas/                        — 21 JSON Schema шапок артефактов
  templates/                              — 21 шаблон артефактов
plugins/sigma-mes-skills/                  — плагин в формате Agent Plugins
  plugin.json, README.md, INSTALL.md, CHANGELOG.md, OPEN-QUESTIONS.md
  skills/<навык>/SKILL.md                 — четыре навыка
  skills/<навык>/references/              — копии plugin-src/shared/ (создаёт sync-shared.sh)
build/codex/
  sync-shared.sh                          — раскладка общих справочников по навыкам
  extract_constitution.py                 — извлечение нормативных текстов из Markdown-версии документа
  checks/run-all.sh                       — приёмка плагина: структурные и нормативные проверки
prompt/0.11.0/                            — пакет промпта, по которому собран плагин
```

Общие справочники правятся только в `plugin-src/shared/`. Копии в `references/` каждого
навыка перезаписываются скриптом; править их вручную запрещено.

## Условия ролей

Роль может дополнять правила Конституции собственными условиями в пределах своих полномочий:
порядок работы, проверки, форматы, условия перехода через гейт. Общее правило: разрешено всё,
что явно не запрещено и не задекларировано Конституцией; при противоречии действует
Конституция.

1. Роль готовит условие в своём навыке, в режиме «Предложить условие роли» (PO-8, FA-13,
   TA-9); роль без своего навыка — в режиме G-4 навыка гейтов. Навык сверяет условие с
   Конституцией и выдаёт готовую запись.
2. ROLE-AI-USE-CASE-OWNER даёт GO.
3. Запись вносится в реестр `plugin-src/shared/role-conditions.yaml` и выходит новой версией
   плагина. Навык применяет условия своей роли в указанных режимах, навык гейтов — условия
   перехода через гейт от всех ролей. Нет условий — всё работает как раньше.

## Установка

```
codex plugin marketplace add petrovich-opendev/sigma-mes-methodology
```

Затем установить `sigma-mes-skills` из Plugins Directory (ChatGPT для десктопа, режим Codex
или Work, после перезапуска приложения) или через `/plugins` в Codex CLI и открыть новый чат.
Для начала работы больше ничего не нужно.

Кто ставил 0.11.0, обновляется командой `codex plugin marketplace upgrade sigma-mes`: та
версия требовала документы и конфигурацию и останавливала работу.

Подробно — `plugins/sigma-mes-skills/INSTALL.md`: требования, подключение маркетплейса,
обновление, начало работы. Необязательно, только расширяет возможности: реестр терминов
(MCP-сервер `sigma_terms`), сохранение артефактов в рабочий репозиторий
(`sigma-mes.config.yaml`), опубликованные условия применения ИИ.

## Проверка

```
sh build/codex/checks/run-all.sh
```

Прогон синхронизирует общие справочники, затем выполняет структурные проверки S-01…S-12 и
нормативные: состав идентификаторов, выведенные коды, обязательные и запрещённые формулировки
в навыках, целостность решений, правила `validation` всех типов артефактов. Код возврата 0
только при отсутствии FAIL.

Требуется `python3` с `PyYAML` и `jsonschema`, а также git-клон репозитория (не
распакованный архив): проверка S-12 берёт перечень файлов из git.

## Открытые вопросы

`plugins/sigma-mes-skills/OPEN-QUESTIONS.md` — вопросы к людям, которые не блокируют работу
плагина: условия применения ИИ не утверждены (Q-01, Q-103) — плагин работает без них и
отмечает это в каждом артефакте, но расхождение с RULE-AI-001 ждёт решения
ROLE-AI-USE-CASE-OWNER; постоянный адрес репозитория; статус черновиков Конституции и
Регламента; неназначенные роли; лицензия (Q-104); отступления от пакета промпта.
